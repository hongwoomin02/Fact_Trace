## 2. 프로젝트의 목적과 구성

영상의 얼굴 조작 여부를 분석하는 기능과 향후 텍스트 근거 대조 기능을 공통 웹서비스에서 제공하는 프로젝트다. 영상 분석은 업로드한 영상에서 얼굴 영역을 추출하고 v6 모델로 REAL/FAKE/UNKNOWN 결과를 반환한다. 텍스트 페이지는 현재 연동 준비 화면이며, 실제 텍스트 분석이 구현되었다고 쓰지 않는다.

- 현재 프론트엔드: React 19, TypeScript, Vite, React Router. 이전 인수인계의 React 18 표기와 다르다.
- 영상 백엔드: Python, FastAPI, Modal. 배포 설정은 T4 GPU, timeout 600초, scaledown_window 300초, max_containers 1.
- 별도 합성 백엔드: FastAPI + FaceFusion CLI 연결 코드. 실 GPU 실행은 미검증이다.
- 페이지: `/`, `/video`, `/text`, `/demo/generate`, `/generate`.
- 두 합성 경로는 모두 DemoGeneratePage를 사용한다. 별도의 GeneratePage/generateApi는 현재 라우트에서 사용하지 않는 이전 코드다.

## 5. 모델과 점수 해석: 반드시 유지할 사실

- 현재 모델은 CLIP ViT-L/14 기반 v6 3-seed 앙상블이며, 상세 학습 정보는 이전 인수인계 자료의 배경 정보다.
- 이번 작업에서 모델 가중치, v6 추론 집계, 임계값을 변경하거나 재학습하지 않았다.
- 실제 코드의 판정은 `video_margin < 0 → FAKE`, `video_margin >= 0 → REAL`이다.
- 이전 첨부의 `0 이하 FAKE` 표기는 현재 코드와 다르다. 실제 코드를 기준으로 쓰되 이 차이를 숨기지 않는다.
- 판정은 반올림 전 margin으로 정해지고 응답 margin/score는 반올림될 수 있으므로, 프론트에서 점수로 판정을 재계산하지 않는다.
- 표시 점수: `100 / (1 + exp(video_margin))`. 유효한 API `fake_score_display`가 있으면 이를 100배하여 우선 사용한다.
- 이름은 **조작 의심 점수**. 통계적으로 보정한 실제 조작 확률이 아니므로 ‘딥페이크 확률 99%’라고 쓰지 않는다.
- UNKNOWN은 오류와 다르다. 유효한 얼굴 분석이 없어 판단할 수 없다는 정상 응답이며 점수는 표시하지 않는다.
- Grad-CAM은 최종 서비스 범위에서 제외되었으므로 구현·추가 제안·완료 주장 금지.

## 7. 중요한 미완료·보완 항목

1. **시연 영상 자산 교체가 필요하다.** 합성 서버의 템플릿 4개와 프론트 mock/result.mp4가 모두 298바이트다. tpl_news.mp4를 브라우저에서 검사하자 미디어 오류 4 및 FFmpegDemuxer open context failed가 발생했다. 실제 재생 가능한, 사용 동의를 받은 원본/샘플 영상으로 교체해야 한다. 다른 4개 파일을 각각 디코딩한 것은 아니다.
2. 실제 Modal의 REAL/FAKE/UNKNOWN/손상 영상 응답 및 운영 프록시를 승인된 환경에서 확인해야 한다. 이번 세션은 GPU 호출이나 배포를 하지 않았다.
3. 합성은 실제 FaceFusion 환경·CUDA·모델 파일·입력 사진·결과 영상 검증이 남아 있다. 모의 실행에서 샘플을 반환하는 것은 얼굴 합성이 아니다.
4. 합성 서버의 작업 저장소·동시성 제한은 프로세스 메모리 기반이다. 서버 재시작 시 작업 정보가 사라져 기존 디스크 파일이 TTL 대상으로 추적되지 않으며, 여러 worker 사이에 작업 상태가 공유되지 않는다. 공개 운영 전 영속 저장/재시작 시 청소/접근 제어/사용량 제한을 설계해야 한다.
5. 합성 사진 검증은 MIME/확장자/용량 중심이며 실제 이미지 디코딩·얼굴 검증을 독립적으로 보장하지 않는다. 요청이 중단되었거나 서버 장애로 삭제가 확인되지 않은 경우 ‘즉시 완전 삭제’를 약속하지 않는다.
6. 텍스트 모듈은 준비 화면이다.
7. 이전 합성 코드 GeneratePage/generateApi는 현재 미사용이고 실제 FaceFusion API와 다른 계약 및 캔버스 기반 시뮬레이션을 포함한다. 재연결 전에 정리해야 한다.
8. Git에 이미 추적된 pyc 캐시가 있다. .gitignore 추가만으로 기존 추적이 제거되지는 않으며, 이번에는 기존 추적 파일을 삭제하지 않았다.
9. 이전 보고서의 성능 수치를 이번 주 신규 실험 결과로 쓰지 않는다.

## 8. 이전 인수인계의 연구·일정 배경

다음은 이전 문서의 기록이며 이번 점검에서 재실험하거나 원본 평가표와 대조하지 않았다.

- DFD 726편 AUC 약 0.909→0.950, KoEBA 66편 Macro F1 약 0.694→0.916, Fake Recall 약 0.565→0.891 기록. 비교 모델·조건을 원본 보고서에서 확인하기 전에는 이번 주 성과 수치로 사용하지 않는다.
- 신규 99편은 REAL/FaceFusion/FSGAN 각 33편이며 이전 기록상 모두 정분류. 모델 선택에 활용된 개발 자료이므로 독립적인 최종 테스트 성능으로 주장할 수 없다.
- 과거 warm/cold 응답 시간도 특정 환경·샘플에서 측정한 기록이다. 이번에는 새로 측정하지 않았다.
- 11월 3~4일 RTX 4090 사용 계획과 FaceFusion/FSGAN 합성 준비는 이전 일정이며 실제 예약·실행 여부 미확인이다.
- REAL 시연은 기존 정상 영상 활용, 본인 얼굴 사진은 합성용 source로 사용할 계획이었다.

## 9. 보고서 작성 형식

다음 순서로 약 2~3쪽 분량의 초안을 작성해 줘.

1. 금주 목표: 기존 v6 모델을 유지하면서 웹 연동과 결과 해석·예외 처리 안정화.
2. 수행 내용: 10/26 작업과 10/27 추가 점검을 구분하고, 요청 흐름·점수 표시·실패 시 사용자 흐름을 설명.
3. 발견 문제와 해결: 재시도 취소 미연결, 본문 수신 timeout 누락, 비정상 응답 렌더링, 임시 파일 정리, 합성 주소/삭제 오류를 표로 정리.
4. 검증 결과: 위 테스트 수와 환경·모의 검증 범위를 정확하게 기재.
5. 한계: 실제 배포/GPU 미검증, 시연 영상 자산 교체, 합성 운영·보관 관리 후속 과제.
6. 다음 주 계획: 정상 시연 자산 확보 → 승인된 실제 API 테스트 → 실제 FaceFusion 환경 검증 → 결과 및 실패 사례 기록.
7. 1분 발표 요약: 모델 성능 향상과 서비스 안정화 성과를 혼동하지 않고 이번 주의 웹서비스 개선점을 설명.

없는 성과 수치나 스크린샷을 만들어 넣지 말고, 필요하면 ‘실제 화면 캡처 삽입 위치’만 표시해 줘. 보고서 작성만 요청받았다면 코드를 수정하거나 commit/push/deploy/GPU 실행을 하지 마.
